# /skill-stat — 스킬 호출 통계

내가 만든 스킬 중 **실제로 쓰이는 게 뭔지** 숫자로 보여준다. OS를 계속 키우다 보면 스킬은 늘어나는데 정작 쓰는 건 서너 개인 상황이 오고, 그때 뭘 남기고 뭘 버릴지 판단할 근거가 이 통계다.

## 데이터 소스

`~/.claude/projects/<프로젝트>/<세션UUID>.jsonl` — Claude Code가 자동으로 남기는 세션 transcript.

**별도 훅이나 설치가 필요 없다.** 스킬 호출은 이미 assistant 메시지의 `tool_use` 블록으로 전부 기록되어 있고, 이 스킬은 그걸 읽기만 한다:

```json
{"type":"assistant","timestamp":"...","cwd":"...","sessionId":"...",
 "message":{"content":[{"type":"tool_use","name":"Skill",
                        "input":{"skill":"guesung:commit","args":"..."}}]}}
```

## 실행

집계는 반드시 아래 스크립트로 한다. **파싱 로직을 매번 즉석에서 짜지 말 것** — 같은 질문에 매번 다른 숫자가 나오면 통계로서 가치가 없다.

```bash
python3 .claude/skills/skill-stat/scripts/skill_stat.py [옵션]
```

### 옵션

| 옵션 | 설명 |
|---|---|
| `--by skill` | 스킬별 호출 횟수·비중·마지막 사용일·사용 프로젝트 수 (**기본값**) |
| `--by project` | 프로젝트별 호출 횟수 |
| `--by day` | 날짜별 호출 추이 |
| `--by recent` | 최근 호출 내역 (시각·스킬·프로젝트·인자) |
| `--days N` | 최근 N일로 제한 |
| `--project <문자열>` | cwd에 해당 문자열이 포함된 호출만 |
| `--here` | 현재 디렉터리 기준으로 필터 |
| `--top N` | 상위 N개만 출력 |
| `--json` | 집계 결과를 JSON으로 (다른 도구에 넘길 때) |

### 요청 유형별 매핑

| 사용자가 이렇게 말하면 | 이렇게 실행 |
|---|---|
| "스킬 통계 보여줘" | `--top 15` |
| "이번 달 뭐 많이 썼어?" | `--days 30 --top 15` |
| "이 프로젝트에서 뭐 썼어?" | `--here` |
| "요즘 스킬 얼마나 쓰나" | `--by day --days 30` |
| "방금 뭐 호출했지?" | `--by recent --top 10` |
| "안 쓰는 스킬 찾아줘" | `--top 100` 후 아래 "사장된 스킬" 절차 |

## 보고 방식

1. 스크립트 출력을 **그대로** 보여준다. 표를 다시 그리거나 숫자를 옮겨 적지 않는다 (옮기다 틀린다).
2. 그 아래에 **해석 2~3줄**을 붙인다. 표만으로는 안 보이는 것만:
   - 상위 1~2개에 쏠려 있는지 (쏠림은 나머지가 죽은 자산이라는 뜻)
   - `마지막 사용`이 오래된 스킬 — 사장 후보
   - `프로젝트` 수가 1인 스킬 — 범용이 아니라 특정 레포 전용일 가능성
3. 숫자에 없는 걸 지어내지 않는다. 특히 **집계에 안 잡히는 것**을 유의:
   - 스킬을 등록만 하고 한 번도 안 쓴 경우 → 호출 0회라 **표에 아예 안 나온다**
   - 오래된 transcript가 정리됐다면 그만큼 누락된다

### 사장된 스킬 찾기

"안 쓰는 스킬" 질문에는 통계만으로 답할 수 없다. 호출 0회인 스킬은 표에 없기 때문이다. 등록된 목록과 대조해야 한다:

```bash
ls .claude/skills/ ~/.claude/skills/ 2>/dev/null
python3 .claude/skills/skill-stat/scripts/skill_stat.py --top 100
```

등록됐는데 표에 없는 것 = 한 번도 안 쓴 스킬. 이걸 별도로 짚어준다.

## 주의

- **읽기 전용이다.** transcript를 수정하거나 지우지 않는다.
- 인자(`args`)에는 사용자가 쓴 문장이 그대로 들어 있다. `--by recent` 출력을 외부에 공유할 때는 내용을 한 번 보고 넘긴다.
- 다른 사람 환경에서 0건이 나오면 경로부터 확인한다. `CLAUDE_CONFIG_DIR`이 설정돼 있으면 스크립트가 그쪽을 본다.

## 설계 의도 (이 레포는 OS 실습 레포이므로 남겨둔다)

- **훅이 아니라 transcript를 소스로 골랐다.** 훅으로 카운터를 쌓는 방법도 있지만 그건 *지금부터*만 쌓인다. transcript에는 과거 호출이 이미 전부 있어서, 설치 0단계로 첫날부터 의미 있는 통계가 나온다. 대신 Claude Code 내부 로그 포맷에 의존하므로, 포맷이 바뀌면 이 스크립트를 고쳐야 한다 — 그 대가를 알고 고른 선택이다.

- **파이썬 스크립트로 고정하고 SKILL.md는 호출법만 담았다.** `gh-commit`처럼 절차를 문서로만 적어두는 방식은 판단이 필요한 작업에 맞다. 반면 집계는 **매번 똑같은 답이 나와야 하는 계산**이다. 모델이 그때그때 파이프라인을 짜면 필터 조건이 미묘하게 달라져 숫자가 흔들린다. "판단은 문서로, 계산은 코드로" 나눈 것.

- **이벤트 uuid로 dedupe한다.** `--resume`나 compaction 때 같은 이벤트가 두 파일에 실릴 수 있다. 안 거르면 자주 이어붙인 세션의 스킬만 부풀어 보인다.

- **경로 비교 전에 NFC 정규화한다.** macOS의 `os.getcwd()`는 한글을 NFD(자모 분리)로 주는데 transcript의 `cwd`는 NFC(완성형)다. 정규화 없이 비교하면 `레포지토리/` 같은 한글 경로에서 `--here`가 **에러 없이 0건**을 반환한다. 실제로 이 레포에서 겪고 고친 버그다 — 조용히 틀리는 종류라서 주석으로 남겨뒀다.

- **표 폭을 `len()`이 아니라 문자 폭으로 계산한다.** 한글은 터미널에서 두 칸을 먹어서, `len()` 기준으로 정렬하면 한글 프로젝트명이 있는 행이 어긋난다.

## 인자

`$ARGUMENTS` — 기간·범위·정렬에 대한 자연어 지시 (선택).
예: `/skill-stat 최근 일주일`, `/skill-stat 이 프로젝트만`, `/skill-stat 안 쓰는 거 찾아줘`
