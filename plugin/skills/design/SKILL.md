# /os:design — 설계 초안 → 사람 확정

OS.md 3절의 **"[AI] 설계 초안 · 막힐 지점 지적"** 이 이 스킬이다. 설계 권한은 사람에게 있고, AI는 **사람이 검토할 재료**를 만든다. 근거와 결정 이력은 [docs/design-stage.md](../../../docs/design-stage.md).

```
/os:work-card ─→ 씨앗 (한 줄 목표 · 막힐 지점 초벌)
        │
        ▼
§0 페이지 읽기
 ① 레포 탐색      Explore → 변경 지점 file:line
 ② 설계서 6항목    목표 · AS-IS · TO-BE · 변경 지점 · 동작 명세 · 범위 밖
 ③ 다이어그램      트리거 해당 시에만. 미해당이면 "해당 없음 + 이유"
 ④ 막힐 지점 → ## 논의 필요
 ⑤ 논의 필요 해소  ★ 한 건씩 묻는다. 0건이 될 때까지
 ⑥ 승인 도장      ★ 사람이 승인해야만 찍는다
        │
        ▼
/os:implement-loop
```

**⑤가 ⑥ 앞에 있다.** 답이 안 나온 항목을 남긴 채로는 승인 질문이 성립하지 않는다. "이 설계 괜찮나요?"를 물으면서 "그런데 3번은 아직 모릅니다"를 같이 내밀면 사람은 모르는 채로 승인한다.

단계 표기는 implement-loop 관례를 따른다 — `§0`은 시작 전 확인, 실제 단계는 `①②③`.

## 노션 접근

개인 업무 로그는 **`notion-home` MCP**로만 읽고 쓴다. `claude.ai Notion`으로 접근하면 404다.

| 식별자 | 값 |
|---|---|
| 개인 업무 로그 database | `5f408e05-0015-4532-bcd8-bd36439bec5a` |
| 개인 업무 로그 data source | `8412989c-11e3-4685-8af9-35299fc6c097` |

## §0. 시작 전 확인

1. **인자 파싱.** 첫 토큰이 `notion.com/…` 이어야 한다. 없으면 멈추고 요구한다. 팀 카드 URL을 주면 안 된다 — 팀 카드는 읽기 전용이고 OS 섹션이 없다.
2. **페이지 읽기.** `API-retrieve-page-markdown`으로 `## 설계서`·`## 논의 필요`를 확보한다. `## 설계서`가 통째로 비어 있으면 work-card를 먼저 돌리라고 안내하고 멈춘다 — 씨앗 없이 설계를 시작하면 슬랙 맥락을 이 스킬이 다시 읽어야 한다.
3. **이미 확정된 페이지인지 확인.** `## 설계서` 안에 확정 도장(§⑥)이 있으면 `AskUserQuestion`으로 묻는다.
   - `다시 설계` → 도장을 지우고 ①부터. 기존 설계서는 **지우지 않고** 아래에 이어 쓴다.
   - `그대로 진행` → 아무것도 하지 않고 `/os:implement-loop` 호출을 안내하며 끝낸다.
4. **레포 경로 판정.** `--repo`가 있으면 그것. 없으면 페이지 속성 `프로젝트`로 아래 표를 역인용한다.

   | `프로젝트` | 레포 경로 |
   |---|---|
   | `넛지헬스케어` | `~/Desktop/레포지토리/cashwalk/` 아래에서 페이지 제목·설계서 키워드로 후보를 좁힌다 |
   | `웹 메모` | `~/Desktop/레포지토리/guesung/web-memo` |
   | 그 외 | `~/Desktop/레포지토리/guesung/` 아래에서 이름이 맞는 것 |

   **후보가 둘 이상이면 `AskUserQuestion`으로 고르게 한다.** 찍지 않는다 — 틀린 레포를 탐색하면 ①의 결과가 전부 쓰레기가 되고, 그 사실이 ⑥에서야 드러난다.
   경로를 끝내 정할 수 없으면 ①을 건너뛰고 ②의 AS-IS·변경 지점을 통째로 `## 논의 필요`로 넘긴다.

## ① 레포 탐색

`Explore` 에이전트를 띄운다. 프롬프트에 **설계서 씨앗과 레포 경로만** 넣는다. 찾을 것은 셋이다.

- 씨앗이 말하는 화면·기능의 **진입점** (라우트 파일 · 페이지 컴포넌트)
- 거기서 갈라지는 **현재 흐름** — 어떤 상태·API·컴포넌트를 거치는가
- 이번에 **고칠 자리** — `path/File.tsx:120` 수준

`--repo`가 cashwalk 밖이면 탐색 깊이를 낮춘다(진입점과 고칠 자리만). 개인 프로젝트는 대개 흐름이 짧아 깊게 파도 나오는 게 없다.

**못 찾은 것은 지어내지 않는다.** 추측한 `file:line`은 없는 것보다 나쁘다 — 구현자가 그 파일을 찾다가 시간을 버리고, 없다는 걸 확인한 뒤에야 추측이었음을 안다. 못 찾았으면 ④로 넘긴다.

## ② 설계서 6항목

`## 설계서`에 아래 순서로 쓴다. **초안이다. 확정은 사람이 한다.**

| 항목 | 내용 | 출처 |
|---|---|---|
| 한 줄 목표 | 이 작업이 무엇을 되게 하는가 | 씨앗 |
| AS-IS | 지금 이 화면·흐름이 어떻게 도는가 | ① 탐색 |
| TO-BE | 무엇이 어떻게 달라지는가 | 씨앗 + ① |
| 변경 지점 | `path/File.tsx:120` 목록. 새로 만들 파일은 `(신규)` | ① 탐색 |
| 동작 명세 | 입력·상태·분기 표 | 씨앗 |
| 범위 밖 | 이번에 안 하는 것 | 씨앗 |

- 씨앗에 없고 레포에서도 확인되지 않는 동작은 **쓰지 않는다.** ④로 넘긴다.
- 기존 설계서를 덮어쓰지 않고 `## 설계서` 아래를 새로 구성한다. 씨앗의 한 줄 목표는 그대로 살린다.
- `범위 밖`을 비워두지 않는다. 비어 있으면 "안 하는 것을 생각해보지 않았다"는 뜻이고, 그게 구현 중 범위가 새는 경로다.

## ③ 다이어그램 — 조건부

아래 표에 **해당할 때만** 그린다. 판단 여지를 남기지 않기 위해 임계값을 숫자로 둔다.

| 트리거 | 그리는 것 | 안 그리는 경우 |
|---|---|---|
| 조건 분기 **2개 이상** (상태 · 권한 · 플랫폼) | `flowchart TD` | 분기 1개 이하 |
| 프론트↔서버 또는 웹↔브릿지 왕복 **2회 이상** | `sequenceDiagram` | 단일 조회 |
| 화면·컴포넌트 상태 **3개 이상** | `stateDiagram-v2` | 상태 2개 이하 |
| 새 파일 **3개 이상** 또는 모듈 경계 변경 | `flowchart LR` | 단일 파일 수정 |

노션에는 **code block(language `mermaid`)** 으로 넣는다. 노션이 그 자리에서 렌더한다. 언어가 거부되면 `plain text` 코드 블록으로 넣고 `## 논의 필요`에 한 줄 남긴다 — 조용히 다른 형식으로 바꾸지 않는다.

전부 미해당이면 다이어그램은 **0개**다. 다만 그때도 `## 설계서` 끝에 한 줄을 남긴다.

```
다이어그램: 해당 없음 (분기 1개 · 단일 파일)
```

안 그린 것이 **판단의 결과인지 빠뜨린 것인지**를 사람이 구별할 수 있어야 한다. 이 줄이 없으면 검토자가 매번 트리거 표를 스스로 다시 돌려야 한다.

다이어그램은 **설계서에 이미 쓴 것만** 그린다. 그림에만 있고 글에는 없는 분기를 만들지 않는다.

## ④ 막힐 지점 → `## 논의 필요`

각 항목은 **`무엇이 불명확한가 → 어느 선택지가 있는가 → 내가 추천하는 쪽과 이유`** 로 쓴다. 추천 없이 질문만 던지지 않는다 — 사람이 판단할 재료를 만드는 게 이 단계의 목적이다.

여기 들어가는 것:

- 씨앗에도 없고 레포에서도 확인 안 되는 동작
- ①에서 변경 지점을 특정하지 못한 부분
- 레포의 현재 구조와 씨앗의 요구가 충돌하는 지점
- 설계서대로 만들면 기존 동작이 깨질 것 같은 자리

## ⑤ 논의 필요 해소

`## 논의 필요`가 0건이 될 때까지 **`AskUserQuestion`으로 한 건씩** 묻는다.

- 한 번에 하나. 답을 받으면 `## 설계서`에 반영하고 그 항목을 `## 논의 필요`에서 지운다.
- 반영으로 다이어그램 트리거가 새로 충족되면 ③을 다시 돌린다.
- 사용자가 "나중에"를 고르면 **페이지를 저장한 채로** 끝낸다. 도장은 찍지 않는다. 재개는 같은 URL로 다시 부르면 된다.
- 사용자가 답하지 않고 자리를 비워도 **가정하고 넘어가지 않는다.** ①의 가정과 다르다 — 여기서 찍은 가정은 설계서 본문이 되고, 구현 루프 전체가 그 위에 쌓인다.

**묻기 전에 여기까지의 결과를 노션에 저장한다.** 사용자가 어떤 답을 하든 ①~④의 결과는 남아 있어야 한다.

## ⑥ 승인 도장

`## 논의 필요`가 0건이 되면 `AskUserQuestion`으로 승인을 묻는다. 질문에는 **설계서 요약과 다이어그램 유무**를 함께 낸다.

- `승인` → `## 설계서` **첫 줄**에 quote 블록으로 도장을 찍는다. 그리고 `/os:implement-loop <페이지 URL>`을 이어서 실행한다.

  ```
  > 설계 확정 · 2026-08-30 14:20 · 사람 승인
  ```

- `보류` → 페이지만 저장하고 끝낸다. 무엇이 남았는지 한 줄로 보고한다.

시각은 승인 응답을 받은 시각이다. 나중에 페이지 편집 이력과 대조할 수 있게 남긴다.

### 강제력의 한계

**AI는 기술적으로 자기 도장을 찍을 수 있다.** 속성이든 본문이든 같은 API로 쓴다. 이건 규칙이지 기계적 강제가 아니다. 진짜로 막으려면 OS.md 4.2의 "원장 항목 → 검사기 승격"처럼 검사기가 도장의 출처를 검증해야 하고, 그건 아직 없다.

그래서 아래를 **하지 않는 것**에 못 박는다.

## 마지막 출력

세 줄. 그 이상 쓰지 않는다.

```
설계서: <페이지 URL>  ·  다이어그램 n개 (또는 "해당 없음")
논의 필요: n건        ← 0건이어야 도장이 찍힌다
확정: 2026-08-30 14:20  (또는 "보류 — <남은 것>")
```

## 하지 않는 것

- **`AskUserQuestion` 승인 응답 없이는 도장을 찍지 않는다.** 사용자가 자리를 비웠거나, 답이 모호하거나, "알아서 해"라고 해도 찍지 않는다. 이 스킬이 존재하는 이유가 그 도장이다.
- 씨앗에도 레포에도 없는 동작을 설계서에 지어내지 않는다. 빈 곳은 `## 논의 필요`로.
- 확인하지 못한 `file:line`을 쓰지 않는다.
- 트리거에 해당하지 않는 다이어그램을 그리지 않는다. 그리고 안 그렸다는 사실을 숨기지 않는다.
- 팀 작업 카드를 건드리지 않는다. 읽기만 한다.
- 코드를 고치지 않는다. 이 스킬은 설계까지다.
- `## TDL`·`## QA 체크리스트`·`## 루프 로그`를 채우지 않는다. implement-loop 몫이다.

## 왜 이렇게 나눴나

- **work-card에서 떼어낸 이유** — work-card는 슬랙과 노션만 보면 되지만 동작 명세는 레포를 열어야 나온다. 필요한 입력이 다르다. 그리고 설계가 틀렸다는 걸 구현 중에 알았을 때, work-card를 다시 부르는 것은 노션 페이지 셋업까지 다시 하는 일이다. **재실행 단위가 곧 스킬 경계다.**

- **다이어그램을 조건부로 둔 이유** — 로그인 버튼 텍스트를 바꾸는 작업에 시퀀스 다이어그램이 붙으면, 읽는 사람은 설계서 전체를 형식적인 것으로 취급하기 시작한다. 다이어그램이 있다는 사실 자체가 "이건 복잡한 작업"이라는 신호여야 값이 있다.

- **"해당 없음"까지 적게 한 이유** — 조건부 규칙의 약점은 침묵이 모호하다는 것이다. 없는 것이 판단인지 누락인지 구별되지 않으면, 검토자가 매번 규칙 표를 스스로 다시 돌려야 한다.

- **⑤를 ⑥ 앞에 둔 이유** — 미해결 항목을 옆에 두고 승인을 물으면 사람은 그것을 포함해 승인해버린다. 설계 권한을 사람에게 남긴다는 원칙이 형식만 남는다.

- **①에서는 가정을 허용하고 ⑤에서는 금지한 이유** — ①의 가정은 "이 파일인 것 같다"는 탐색 결과라 ④에서 사람이 바로잡을 수 있다. ⑤의 가정은 설계서 본문이 되고, 구현 루프 전체가 그 위에 쌓인다. 되돌리는 비용이 다르다.
