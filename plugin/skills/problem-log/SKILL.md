# /os:problem-log — 해결한 문제를 일지에 남긴다

**기록하기 전에 반드시 사람의 승인을 받는다.** 초안을 보여주고 답을 들은 뒤에만 노션에 쓴다.

**호출은 사용자가 시키지 않아도 한다.** ①의 판단 기준에 걸리는 일이 대화 중에 있었으면, 요청을 기다리지 않고 초안을 만들어 ②로 간다. 기록할 게 없다고 판단했으면 아무 말도 하지 않는다 — "기록할 게 없습니다"를 매번 말하면 그게 소음이 된다.

**호출과 승인은 다른 문제다.** 호출은 사람이 잊어도 되게 자동으로, 기록은 사람이 확인한 것만. 자동으로 하는 것은 *물어보러 오는 일*이지 *쓰는 일*이 아니다.

## 저장소 — 노션 "문제 해결 일지DB" (guesung, `notion-home` MCP)

| 식별자 | 값 |
|---|---|
| database | `35189de0-2fde-8085-9688-d281c81eb6b2` |
| data source | `35189de0-2fde-80ec-895d-000bb8b2945f` |

| 속성 | 타입 | 채우는 규칙 |
|---|---|---|
| `이름` | title | **증상** 한 줄. 원인이 아니라 겉으로 드러난 현상 (예: `드롭다운이 열린 상태의 Escape가 메모 상세까지 닫음`) |
| `상황` | rich_text | 무엇이 어떻게 안 됐나. 증상 · 에러 메시지 · 재현 조건. 코드 식별자는 인라인 코드로 |
| `원인` | rich_text | 왜 그랬나 + 확인한 근거. 못 밝혔으면 `미확인 — 우회함` |
| `해결 방법` | rich_text | 무엇을 바꿔서 뚫었나. 커밋 해시나 `파일:라인`. 아직이면 `(아직 해결은 X)`로 시작 |
| `유형` | select | 아래 7개 중 하나를 **제안**하고 승인 때 함께 확인받는다 |
| `프로젝트` | select | 작업한 레포 경로로 정한다 (§프로젝트 판정). 판정이 안 서면 비운다 |
| `날짜` | date | 오늘 |
| `트레이드 오프 / 해결 과정` | rich_text | 다른 선택지가 있었고 그중 골랐을 때만. 없으면 비운다 |
| `메모` | rich_text | 업무 로그 페이지 mention · PR 링크 |

`유형` 선택지: `버그` · `고민` · `궁금증` · `학습` · `상용 배포 이슈` · `힘들게 해결한 버그` · `구현`

### 프로젝트 판정

`프로젝트` 선택지는 **`넛지헬스케어` · `웹 메모` 둘뿐이다.** 없는 옵션을 새로 만들지 않는다 — 자동화가 select를 늘리기 시작하면 DB가 금방 지저분해진다.

| 작업한 레포 경로 | `프로젝트` |
|---|---|
| `레포지토리/cashwalk/**` | `넛지헬스케어` |
| `레포지토리/guesung/web-memo` | `웹 메모` |
| 그 외 · 경로를 모름 | **비운다** |

`--work-card`를 받았으면 그 업무 로그 페이지의 `프로젝트` 속성을 그대로 따른다. 같은 작업의 두 기록이 다른 프로젝트로 갈리지 않게 한다.

> 기존 행들은 `원인`과 `유형`이 비어 있다. 손으로 쓰다 빠진 칸이다. **이 스킬의 값은 그 두 칸을 채우는 데 있다** — 원인 없는 일지는 나중에 검색해도 쓸모가 없고, 유형 없는 일지는 "자주 막히는 유형"을 셀 수 없다.

## ① 초안

무엇을 남길지 고른다. 판단 기준은 **"다음에 같은 걸 만나면 이 기록을 찾아볼 것인가"**.

| 남긴다 | 남기지 않는다 |
|---|---|
| 원인을 찾는 데 시간이 걸린 것 | 오타·문법 오류처럼 즉시 보인 것 |
| 처음에 세운 가설이 틀렸던 것 | 설계대로 순조롭게 짠 것 |
| 우회만 하고 원인을 못 밝힌 것 | 이미 일지에 같은 항목이 있는 것 |

세 칸을 채운다. **원인 칸에는 확인한 것만 쓴다** — 근거 없이 그럴듯한 설명을 넣으면 그 기록이 나중에 사람을 잘못된 방향으로 보낸다. 확인하지 못했으면 `미확인 — 우회함`이 정답이다.

중복 확인: `API-query-data-source`로 최근 20행의 `이름`을 훑어 같은 증상이 있는지 본다. 있으면 새 행 대신 그 행을 갱신할지 ②에서 함께 묻는다.

## ② 승인 — 여기서 멈춘다

초안 **전문**을 사용자에게 보여준다. 요약하지 않는다. 사람이 읽고 고칠 수 있어야 승인이 의미가 있다.

```
제목   : <이름>
유형   : <제안> (버그 / 고민 / 궁금증 / 학습 / 상용 배포 이슈 / 힘들게 해결한 버그 / 구현)
프로젝트 : <넛지헬스케어 | 웹 메모 | (비움)>

상황 : <…>
원인 : <…>
해결 방법 : <…>
```

그리고 `AskUserQuestion`으로 묻는다.

| 답 | 하는 것 |
|---|---|
| 그대로 기록 | ③으로 |
| 고쳐서 기록 | 무엇을 고칠지 듣고 초안을 고친 뒤 **다시 ②** |
| 기록 안 함 | 아무것도 쓰지 않고 끝낸다 |

여러 건이면 **한 건씩** 묻는다. 한꺼번에 던지면 사람이 대충 넘기고, 그러면 승인 단계가 형식이 된다.

## ③ 기록

`API-post-page`로 data source `35189de0-2fde-80ec-895d-000bb8b2945f`에 행을 만든다.
`--work-card`를 받았으면 `메모`에 그 페이지 mention을 넣는다.

마지막 출력은 한 줄: `일지: <제목> — <행 URL>`.

## 정지 조건

| | 조건 | 남기는 것 |
|---|---|---|
| A | 사용자가 답하지 않음 | 초안을 그대로 출력하고 끝낸다. **승인 없이 쓰지 않는다** |
| B | 노션 접근 실패 (개인 DB는 `notion-home`) | 초안 전문과 에러. 사람이 손으로 옮길 수 있게 |

## 하지 않는 것

- 승인 없이 행을 만들지 않는다. 이 스킬의 존재 이유가 그 승인이다.
- `프로젝트` select에 없는 옵션을 새로 만들지 않는다. 판정이 안 서면 비운 채 두고 승인 화면에 `(비움)`으로 보여준다.
- 이미 있는 행과 같은 증상이면 새 행 대신 갱신을 제안한다.

## 왜 이렇게 나눴나

- **승인을 강제하는 이유** — 일지는 사람이 나중에 자기 언어로 검색할 것이다. AI가 정리한 문장은 그럴듯하지만 사람의 기억과 어긋난 단어를 쓰기 쉽다. ②에서 한 번 손대게 하면 그 어긋남이 사라진다.
- **호출은 자동, 기록은 승인으로 나눈 이유** — 이 둘을 묶어 생각하기 쉽지만 비용이 다르다. **호출을 사람에게 맡기면 그냥 잊힌다** — 문제를 막 뚫은 사람은 다음 작업으로 넘어가지 일지를 떠올리지 않는다. 반면 **기록을 자동으로 하면 틀린 원인이 조용히 쌓인다.** 그래서 AI가 물어보러 오는 것은 자동으로, 노션에 쓰는 것은 사람의 확인으로 나눴다.
- **`원인`에 `미확인 — 우회함`을 허용하는 이유** — 빈칸으로 두면 "안 적었나 보다"가 되고, 추측을 적으면 거짓이 된다. 못 밝혔다는 사실 자체가 정보다. 나중에 같은 증상이 재발하면 그 칸이 바로 단서가 된다.
- **DB 한 곳에 모으는 이유** — 4주차에 "자주 막히는 유형"을 세려면 한 곳에 있어야 한다. 작업 페이지마다 흩어지면 셀 수 없다.
