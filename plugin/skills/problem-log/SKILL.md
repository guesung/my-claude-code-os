# /os:problem-log — 해결한 문제를 일지에 남긴다

**묻지 않고 기록한다.** 초안을 만들고 노션에 쓴 뒤, 전문과 행 링크를 보고한다. 사용자는 그걸 읽고 고칠 게 있으면 말한다.

**사용자가 시키지 않아도 스스로 호출한다.** ①의 판단 기준에 걸리는 일이 대화 중에 있었으면, 요청을 기다리지 않고 실행한다. 기록할 게 없다고 판단했으면 아무 말도 하지 않는다 — "기록할 게 없습니다"를 매번 말하면 그게 소음이 된다.

## 저장소 — 노션 "문제 해결 일지DB" (guesung, `notion-home` MCP)

| 식별자 | 값 |
|---|---|
| database | `35189de0-2fde-8085-9688-d281c81eb6b2` |
| data source | `35189de0-2fde-80ec-895d-000bb8b2945f` |

| 속성 | 타입 | 채우는 규칙 |
|---|---|---|
| `이름` | title | **증상** 한 줄. 원인이 아니라 겉으로 드러난 현상 (예: `드롭다운이 열린 상태의 Escape가 메모 상세까지 닫음`) |
| `상황` | rich_text | 무엇이 어떻게 안 됐나. 증상 · 에러 메시지 · 재현 조건. 코드 식별자는 인라인 코드로 |
| `원인` | rich_text | 왜 그랬나 + 확인한 근거. 못 밝혔으면 `미확인 — 우회함` |
| `해결 방법` | rich_text | 무엇을 바꿔서 뚫었나. 커밋 해시나 `파일:라인`. 아직이면 `(아직 해결은 X)`로 시작 |
| `유형` | select | 아래 7개 중 하나를 **제안**하고 승인 때 함께 확인받는다 |
| `프로젝트` | select | 작업한 레포 경로로 정한다 (§프로젝트 판정). 판정이 안 서면 비운다 |
| `날짜` | date | 오늘 |
| `트레이드 오프 / 해결 과정` | rich_text | 다른 선택지가 있었고 그중 골랐을 때만. 없으면 비운다 |
| `메모` | rich_text | 업무 로그 페이지 mention · PR 링크 |

`유형` 선택지: `버그` · `고민` · `궁금증` · `학습` · `상용 배포 이슈` · `힘들게 해결한 버그` · `구현`

### 프로젝트 판정

`프로젝트` 선택지는 **`넛지헬스케어` · `웹 메모` 둘뿐이다.** 없는 옵션을 새로 만들지 않는다 — 자동화가 select를 늘리기 시작하면 DB가 금방 지저분해진다.

| 작업한 레포 경로 | `프로젝트` |
|---|---|
| `레포지토리/cashwalk/**` | `넛지헬스케어` |
| `레포지토리/guesung/web-memo` | `웹 메모` |
| 그 외 · 경로를 모름 | **비운다** |

`--work-card`를 받았으면 그 업무 로그 페이지의 `프로젝트` 속성을 그대로 따른다. 같은 작업의 두 기록이 다른 프로젝트로 갈리지 않게 한다.

> 기존 행들은 `원인`과 `유형`이 비어 있다. 손으로 쓰다 빠진 칸이다. **이 스킬의 값은 그 두 칸을 채우는 데 있다** — 원인 없는 일지는 나중에 검색해도 쓸모가 없고, 유형 없는 일지는 "자주 막히는 유형"을 셀 수 없다.

## ① 초안

무엇을 남길지 고른다. 판단 기준은 **"다음에 같은 걸 만나면 이 기록을 찾아볼 것인가"**.

| 남긴다 | 남기지 않는다 |
|---|---|
| 원인을 찾는 데 시간이 걸린 것 | 오타·문법 오류처럼 즉시 보인 것 |
| 처음에 세운 가설이 틀렸던 것 | 설계대로 순조롭게 짠 것 |
| 우회만 하고 원인을 못 밝힌 것 | 이미 일지에 같은 항목이 있는 것 |

세 칸을 채운다. **원인 칸에는 확인한 것만 쓴다** — 근거 없이 그럴듯한 설명을 넣으면 그 기록이 나중에 사람을 잘못된 방향으로 보낸다. 확인하지 못했으면 `미확인 — 우회함`이 정답이다. 승인 단계가 없으므로 이 규칙을 지키는 것은 전적으로 이 스킬의 몫이다.

중복 확인: `API-query-data-source`로 최근 20행의 `이름`을 훑어 같은 증상이 있는지 본다. 있으면 새 행을 만들지 않고 **그 행을 갱신한다**(②).

## ② 기록

`API-post-page`로 data source `35189de0-2fde-80ec-895d-000bb8b2945f`에 행을 만든다.
`--work-card`를 받았으면 `메모`에 그 페이지 mention을 넣는다.

중복이 있으면 새 행 대신 **그 행을 갱신한다**(`API-patch-page`). 같은 증상이 두 행으로 갈리면 4주차 집계가 어긋난다.

## ③ 보고 — 전문을 편다

기록한 뒤 **전문**을 출력한다. 요약하지 않는다. 승인을 없앤 대신, 사람이 **읽고 바로 고칠 수 있는 자리**가 여기다.

```
일지: <제목> — <행 URL>   (갱신이면 "갱신: …")
유형: <선택> · 프로젝트: <넛지헬스케어 | 웹 메모 | (비움)>

상황 : <…>
원인 : <…>
해결 방법 : <…>

고칠 게 있으면 말씀해 주세요. 행을 바로 수정합니다.
```

여러 건이면 건마다 이 블록을 반복한다. 사용자가 "2번 원인 틀렸어"처럼 지목하면 `API-patch-page`로 그 행만 고친다.

## 정지 조건

| | 조건 | 남기는 것 |
|---|---|---|
| A | 노션 접근 실패 (개인 DB는 `notion-home`) | 초안 전문과 에러. 사람이 손으로 옮길 수 있게 |
| B | `유형`을 고를 수 없음 | 고르지 못한 채로 쓰지 말고, 7개 중 가장 가까운 것을 쓰고 보고에 `유형 확실치 않음`을 덧붙인다 |

## 하지 않는 것

- **`원인`에 확인하지 않은 것을 쓰지 않는다.** 승인 단계가 없어졌으므로 이 규칙이 유일한 방어다. 근거를 대지 못하면 `미확인 — 우회함`이다.
- `프로젝트` select에 없는 옵션을 새로 만들지 않는다. 판정이 안 서면 비운 채 두고 보고에 `(비움)`으로 표시한다.
- 이미 있는 행과 같은 증상이면 새 행을 만들지 않는다. 갱신한다.
- 기록할 게 없을 때 "기록할 게 없습니다"를 말하지 않는다. 조용히 넘어간다.
- ①의 판단 기준에 걸리지 않는 것(오타 · 순조롭게 짠 것)을 기록하지 않는다. **묻지 않게 됐다고 문턱을 낮추면 일지가 로그가 되고, 로그는 아무도 안 읽는다.**

## 왜 이렇게 나눴나

- **승인을 없앤 이유** — 원래는 "AI가 쓴 문장이 사람의 기억과 어긋난 단어를 쓴다"를 막으려고 승인을 뒀다. 그런데 그 어긋남은 **기록 뒤에 고쳐도 똑같이 고쳐진다.** 반면 승인은 매번 사람을 멈춰 세웠고, 멈춤이 잦으면 "기록 안 함"을 고르게 되어 일지 자체가 안 쌓인다. 그래서 **비용이 큰 쪽(사전 승인)을 빼고, 값이 같은 쪽(사후 수정)을 남겼다.** ③이 그 자리다.

- **대신 `원인` 규칙을 강화한 이유** — 승인이 걸러주던 것 중 사후에 못 고치는 게 하나 있다. **그럴듯한 추측이 원인 칸에 들어가는 것**이다. 사람이 읽어도 그럴듯하면 그냥 넘어가고, 그 기록은 나중에 자기를 잘못된 방향으로 보낸다. 그래서 추측 금지를 `하지 않는 것` 맨 위로 올렸다.

- **문턱을 명시적으로 지킨 이유** — 승인이 사라지면 "일단 남기고 보자"가 되기 쉽다. 그러면 일지가 로그가 된다. ①의 판단 기준이 이제 유일한 필터다.

- **`원인`에 `미확인 — 우회함`을 허용하는 이유** — 빈칸으로 두면 "안 적었나 보다"가 되고, 추측을 적으면 거짓이 된다. 못 밝혔다는 사실 자체가 정보다. 나중에 같은 증상이 재발하면 그 칸이 바로 단서가 된다.

- **DB 한 곳에 모으는 이유** — 4주차에 "자주 막히는 유형"을 세려면 한 곳에 있어야 한다. 작업 페이지마다 흩어지면 셀 수 없다.
